# Web UI i18n

## Decision

Add server-rendered UI localization for `/service/web` and public clip pages using `github.com/nicksnyder/go-i18n/v2` with embedded TOML catalogs `pkg/i18n/locales/{en,zh}.toml` (one file per language; go-i18n reads the language tag from the filename). A leaf message ID that is also a prefix of another ID in the same file uses a quoted TOML table (`["error.validation"]`) so it does not nest with its children. Locale travels on the request context; HTMX partials render in the active language.

UI locale is **separate** from `flowbot.language`, which continues to control ChatAgent / LLM reply language only.

## Cookie contract

| Cookie | Values | Maps to |
|--------|--------|---------|
| `flowbot-lang` | `en` (default), `zh` | BCP 47 `en`, `zh-Hans` |

Switch: `POST /service/web/locale` (no auth required) → Set-Cookie → `HX-Refresh` full reload.

## Middleware

- `/service/web`: `localeMiddleware` runs **before** CSRF.
- `/c/*` (public clip): `localeMiddleware` before clip handler (reads same cookie; no cookie → `en`).

Fiber v3 uses `c.SetContext(i18n.WithLocalizer(...))`.

## Known limits

- Unmapped **`life: …` domain errors** may still surface English.
- **`flowbot.ui_language` instance default** not implemented; cookie-only locale selection.
- Dynamic `err.Error()` from providers/stores may still surface English technical detail inside toasts.
- **Settings field descriptions**: `settings_desc.zh.toml` (generated by `go generate ./pkg/config/...`; preserves existing zh strings). English uses struct godoc via `i18n.TDefault`.
- BDD specs asserting English nav text may need `AttachLocaleForTest(req, en)` or selector changes.
- Technical placeholders (field examples like `my-step`, `git *`, `uid`) stay literal; not product copy.
