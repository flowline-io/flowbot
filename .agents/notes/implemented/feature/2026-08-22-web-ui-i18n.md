# Web UI i18n (Phase 1)

## Decision

Add server-rendered UI localization for `/service/web` using `github.com/nicksnyder/go-i18n/v2` with embedded TOML in `pkg/i18n/locales/`. Locale travels on the request context; HTMX partials render in the active language.

UI locale is **separate** from `flowbot.language`, which continues to control ChatAgent / LLM reply language only.

## Cookie contract

| Cookie | Values | Maps to |
|--------|--------|---------|
| `flowbot-lang` | `en` (default), `zh` | BCP 47 `en`, `zh-Hans` |

Switch: `POST /service/web/locale` (no auth required) → Set-Cookie → `HX-Refresh` full reload.

## Middleware

On `/service/web`: `localeMiddleware` runs **before** CSRF. Fiber v3 uses `c.SetContext(i18n.WithLocalizer(...))`.

## Phase 1 scope

Translated: main/auth layouts (nav, themes, logout confirm), login/setup/2FA forms, confirm modal defaults, command palette static pages, login auth errors, client HTMX error toasts (`#flowbot-i18n`).

Not translated (expected UX gap until Phase 2):

- Business page `PageHeader` titles and body copy
- Per-page `data-confirm` business messages
- Handler `toastError` / `setShowToast` outside login/auth
- ChatAgent, pipeline editor, Life page content, public clip layout

## Phase 2

- Page headers and module copy via message IDs
- Handler toast migration
- `chatagent-*.js` and large templates
