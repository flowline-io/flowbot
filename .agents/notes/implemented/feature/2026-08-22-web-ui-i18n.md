# Web UI i18n

## Decision

Add server-rendered UI localization for `/service/web` and public clip pages using `github.com/nicksnyder/go-i18n/v2` with embedded TOML catalogs `pkg/i18n/locales/{en,zh}.toml` (one file per language; go-i18n reads the language tag from the filename). A leaf message ID that is also a prefix of another ID in the same file uses a quoted TOML table (`["error.validation"]`) so it does not nest with its children. Locale travels on the request context; HTMX partials render in the active language.

UI locale is **separate** from `flowbot.language`, which continues to control ChatAgent / LLM reply language only.

## Cookie contract

| Cookie | Values | Maps to |
|--------|--------|---------|
| `flowbot-lang` | `en` (default), `zh` | BCP 47 `en`, `zh-Hans` |

Switch: `POST /service/web/locale` (no auth required) → Set-Cookie → `HX-Refresh` full reload.

## Middleware

- `/service/web`: `localeMiddleware` runs **before** CSRF.
- `/c/*` (public clip): `localeMiddleware` before clip handler (reads same cookie; no cookie → `en`).

Fiber v3 uses `c.SetContext(i18n.WithLocalizer(...))`.

## Phase 1 scope (complete)

Translated: main/auth layouts (nav, themes, logout confirm), login/setup/2FA forms, confirm modal defaults, command palette static pages, login auth errors, client HTMX error toasts (`#flowbot-i18n`).

## Phase 2 scope (complete)

- **Infrastructure**: `TData`, `PageHeader` / `PageHeaderLiteral`, `webMsg*` / `toastErrorKey` helpers in `internal/modules/web/utils.go`.
- **Message IDs**: `page.*`, `toast.*`, `confirm.*`, `life.*`, `clip.*`, `client.*` in `locales/{en,zh}.toml` (embedded via `locales/*.toml`).
- **Page headers**: ~30 page templates migrated to i18n keys or literals.
- **data-confirm**: 19 templ files; dynamic confirms use `TData`.
- **Handler toasts**: 13 webservices use `webMsg` / `setShowToastKey` / `renderFormErrorKey`.
- **life.templ**: shell, 10 sub-pages, confirms, placeholders, pager, rewards cooldown copy.
- **clip**: layout + page + `clip-copy.js`; locale middleware on `/c`.
- **Client JS**: pipeline-editor, chatagent (chat/approval/thread/codeblocks/context/todos/slash), command-palette, function-editor, life/pipeline/workflow/function stats, pipeline-run-live, hub-app-logs, app.js page-status helpers.

## Known Phase 2 limits

- **`life: …` domain errors** from `internal/modules/life` remain English (no stable message IDs).
- **`flowbot.ui_language` instance default** not implemented; cookie-only locale selection.
- Dynamic `err.Error()` from providers/stores may still surface English technical detail inside toasts.
- BDD specs asserting English nav text may need `AttachLocaleForTest(req, en)` or selector changes.
- Remaining table empty states outside token/function tables may still be English until migrated.
