# Agent Note: Pin go.yaml.in/yaml/v4 to rc.3

Status: implemented

## Problem

`go tool task` and `go tool actionlint` are compiled from this module, so they use the yaml version Minimum Version Selection picks for the whole graph. `github.com/securego/gosec/v2` v2.29.0 requires `go.yaml.in/yaml/v4` v4.0.0-rc.6. That release changed `TypeError.Errors` from `[]*UnmarshalError` to `[]string` and removed `ParserError`. Task v3.48.0 and actionlint v1.7.11 still call `.Err` / `.Line` / `.Column` on those values, so `go tool task lint` fails before any linter runs.

## Decision

`go.mod` replaces `go.yaml.in/yaml/v4` with v4.0.0-rc.3, the version those two tools require. The flowbot module does not import `go.yaml.in/yaml/v4`.

## Alternatives considered

- **Upgrade Task to v3.54.0.** It moved back to `go.yaml.in/yaml/v3` and would compile, but `lint` also runs actionlint v1.7.11, which still needs the rc.3 error types. A Task bump does not unblock lint.
- **Upgrade actionlint.** No release targets rc.6. The open upstream change is [rhysd/actionlint#730](https://github.com/rhysd/actionlint/pull/730).
- **Drop the gosec tool dependency that selects rc.6.** Rejected: gosec stays; the pin is narrower than removing a security check.

## Consequences

- `go tool task` and `go tool actionlint` build against yaml v4 rc.3.
- Remove the replace after Task and actionlint both build against the yaml version the rest of the graph selects.

## Verification

`go tool task --version` and `go tool actionlint -version` compile and print a version.
