# Agent Note: Upgrade templ to v0.3.1070

Status: implemented

## Problem

`github.com/a-h/templ` was pinned at v0.3.1020. v0.3.1070 narrows `ResolveAttributeValue` to stringable, numeric, bool, and `ComponentScript` values. Boolean HTML attributes written as `selected={ templ.KV(cond, true) }` no longer compile because `templ.KeyValue[bool, bool]` is not in that set.

## Decision

Upgrade `github.com/a-h/templ` to v0.3.1070 (`go.mod` require and `tool` `cmd/templ`). Replace boolean-attribute `templ.KV(cond, true)` with templ's boolean attribute syntax `selected?={ cond }`, matching `token_usage.templ` and `life.templ`. Keep `templ.KV` only for conditional CSS class expressions.

## Alternatives considered

- Stay on v0.3.1020.
  - Rejected; the bump is a patch of the current templ line and the compile break is a local template misuse, not a missing feature.
- Keep `selected={ cond }` (plain bool, not `?=`).
  - Rejected; `selected?={ cond }` already owns this pattern in the repo and omits the attribute when false instead of emitting `selected="false"`.

## Consequences

- Regenerated `*_templ.go` files follow the v0.3.1070 generator.
- New boolean HTML attributes must use `attr?={ bool }`, not `templ.KV`.

## Verification

- `go.mod` requires `github.com/a-h/templ v0.3.1070`
- `pkg/views/partials/{agent_scheduled_task_state_form,event_filters,event_pagination}.templ` use `selected?=`
- `go tool templ generate` then `go test ./pkg/views/...` compile
