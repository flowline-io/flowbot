# Agent Note: Upgrade toolchain to Go 1.27.1

Status: implemented

## Problem

The project was pinned to Go 1.26.6 while Go 1.27.1 is the current stable patch. Keeping an older minor blocks language/toolchain fixes and forces contributors and CI onto a lagging compiler.

## Decision

Require Go 1.27.1 everywhere the version is owned:

- Root `go.mod` language line: `go 1.27.1`
- CI `actions/setup-go` pins: `go-version: '1.27.1'` (same exact-patch policy as [CI setup-go patch pin](./2026-08-18-ci-setup-go-patch-pin.md))
- App image builder: `golang:1.27`
- Agent sandbox `GO_VERSION=1.27.1` and FaaS smoke / `pkg/exec` generated module language line: `go 1.27`

## Alternatives considered

- Stay on 1.26.x until a feature forces the bump.
  - Rejected; 1.27 is stable and the repo already pins exact patches, so the cost of upgrading now is low.
- Pin CI to `'^1.27'` and let the runner pick any 1.27.x.
  - Rejected; same cache/non-determinism failure mode documented in the setup-go patch pin note.

## Consequences

- Local and CI toolchains must be at least 1.27.1.
- Agent sandbox images that still ship 1.26.6 are incompatible with FaaS modules that declare `go 1.27` under `GOTOOLCHAIN=local`; rebuild/publish the sandbox image with the new `GO_VERSION`.
- Docs and requirement lines (`AGENTS.md`, `README.md`, `CONTRIBUTING.md`, `docs/agent/agent-sandbox.md`) state 1.27.1+.
- `task build` no longer sets `GOEXPERIMENT=goroutineleakprofile`: Go 1.27 deletes that experiment and ships the `goroutineleak` pprof profile by default.

## Verification

- `go.mod` declares `go 1.27.1`
- Workflows under `.github/workflows/` that pin `go-version` use `1.27.1`
- `deployments/Dockerfile` and `deployments/agent-sandbox/Dockerfile` match the new minor/patch
- `pkg/exec` FaaS `go.mod` contents use `go 1.27`
- `taskfile.yaml` `build` runs plain `go build` without `GOEXPERIMENT=goroutineleakprofile`
