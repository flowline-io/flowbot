# Agent Note: Upgrade templ to v0.3.1100

Status: implemented

## Problem

Bumping `github.com/a-h/templ` from v0.3.1070 to v0.3.1100 without regenerating `*_templ.go` fails to compile: the v0.3.1070 generator emits `templ.ResolveAttributeValue` and `templ.JoinURLErrs`, and v0.3.1100 removes those runtime helpers (security rewrite of attribute / URL expression resolution via `templruntime.NewAttributeExpression`).

## Decision

Upgrade `github.com/a-h/templ` to v0.3.1100 (`go.mod` require and `tool` `cmd/templ`) and regenerate every template with `go tool templ generate` so committed `*_templ.go` matches the runtime. Keep CLI and runtime on the same module version; never bump one without regenerating.

Supersedes the regenerate step of [2026-10-09-templ-0.3.1070-upgrade.md](2026-10-09-templ-0.3.1070-upgrade.md) for the generator/runtime contract; boolean `attr?={ bool }` guidance from that note still applies.

## Alternatives considered

- Stay on v0.3.1070.
  - Rejected; v0.3.1100 includes security fixes for dynamic / mixed-case attributes and URL attributes.
- Bump `go.mod` only and leave committed `*_templ.go` unchanged.
  - Rejected; that is the failure mode (`undefined: templ.ResolveAttributeValue` / `JoinURLErrs`).

## Consequences

- Regenerated `*_templ.go` call `templruntime.NewAttributeExpression(...).Resolve` / `ResolveURL` instead of `ResolveAttributeValue` / `JoinURLErrs`.
- Dynamic event-handler attributes must use `templ.JSFuncCall` / `templ.JSUnsafeFuncCall` (plain strings become `FailedSanitizationJS`). `EmptyStateOnClickCTA` wraps trusted server-owned JS with `JSUnsafeFuncCall`.
- Any future templ bump must run `go tool task templ` (or `go tool templ generate`) in the same change.

## Verification

- `go.mod` requires `github.com/a-h/templ v0.3.1100`
- Generated files declare `templ: version: v0.3.1100` and do not reference `templ.ResolveAttributeValue` or `templ.JoinURLErrs`
- `go tool task lint` and `go test ./pkg/views/...` pass
