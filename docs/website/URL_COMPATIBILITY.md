# URL Compatibility Matrix

## Canonical Host

- Production canonical host: `https://flowline-io.github.io`
- Canonical path shape: keep `.html` for stable entry files; homepage canonical is `/`
- Build-time SEO config: `cmd/composer/action/webdoc/seo.yaml` (not published to Pages)
- Entry-page title/description/canonical/OG/Twitter (and homepage JSON-LD) are injected by `webdoc` between `<!-- seo:start -->` and `<!-- seo:end -->` from `seo.yaml` `entry_pages`
- Do not hand-edit SEO tags inside those markers; change `seo.yaml` and re-run `webdoc`

## Stable Entry Points

The following entry pages are intentionally preserved as stable URLs:

- `index.html`
- `design.html`
- `api.html`
- `tutorials.html`
- `skills.html`
- `404.html`

## Sitemap and robots

- `docs/website/sitemap.xml` and `docs/website/robots.txt` are generated by `go run ./cmd/composer webdoc` from `seo.yaml`
- Phase-1 sitemap whitelist: `/`, `/design.html`, `/api.html`, `/tutorials.html`, `/skills.html`
- Generated documentation pages receive canonical + basic social meta tags but are not bulk-added to the sitemap until a later phase
- `404.html` is excluded from the sitemap and uses `noindex`

## Navigation Strategy

- Use relative links between website pages (`index.html`, `design.html`, and so on).
- Use `docs/getting-started/` as the docs entry point from website pages.
- Keep GitHub links absolute to avoid repository path ambiguity.

## Fallback Behavior

- If a route cannot be resolved, `404.html` provides recovery links to `index.html` and `docs/getting-started/`.
- Reordering navigation labels must not remove or rename the stable entry files above.
